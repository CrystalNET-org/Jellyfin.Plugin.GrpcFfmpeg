gRPC-ffmpeg

Runs Jellyfin's ffmpeg and ffprobe commands on remote grpc-ffmpeg workers. The media library and Jellyfin's transcode, cache and temp directories must be available at the same paths on Jellyfin and on the workers; Save and test connection checks them.

Worker

Host name or IP address of the worker, service or load balancer.
Must match the worker's VALID_TOKEN.
Certificate used to verify the worker when TLS is enabled.

Fallback

Recommended. Commands run on this server's ffmpeg when no worker is reachable or the workers reject the token. Jellyfin checks ffmpeg at startup and does not start if that fails, so without the fallback a worker outage or a wrong token keeps Jellyfin from starting. With the fallback, Jellyfin starts and library scans and direct play keep working; transcodes that need the workers' hardware acceleration fail until the workers are back. The status above shows when commands fall back.
Leave empty to use the ffmpeg Jellyfin would use without this plugin (not found).
Attempts while no worker is reachable or all are busy, waiting 1s, 2s, 4s and then 5s between them. After a command found no worker, commands in the next 20 seconds go to the fallback right away.

Console

Commands run through the client with their exit codes, the client's messages (retries, authentication errors, fallback) and the end of ffmpeg's error output for failed commands. Kept in memory only (last 1000 lines).

                        

                            
                            
                        

                    


                    

                        
Experimental: hardware classes

                        

                            
                            

                                A prototype. Each class is its own worker pool. A playback session keeps one class for its whole life,
                                and the commands go to that class's workers. Library scans, trickplay, image extraction and Jellyfin's
                                startup checks keep using Jellyfin's own transcoding settings and the worker above.
                                Only Intel QSV and NVIDIA NVENC are supported, and Jellyfin's dashboard still shows its global settings.
                                Turning this on or off takes effect after restarting Jellyfin.
                            

                        

                        

                            
                            
Automatic skips classes whose workers were just found unreachable,
                                prefers classes that can decode the video in hardware, then the class with the fewest running
                                transcodes per weight, then one that can encode the client's preferred codec.
